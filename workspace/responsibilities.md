# 仓库职责与跨仓库路由

本文是九个受管仓库的**人类可读职责与内容路由唯一规范**。
[repositories.json](repositories.json) 只声明管理哪些仓库、它们的运行时归属
（`tier`）、所有权和 Git 远程；本文只规定内容应该由哪个仓库维护。各仓库内部的
架构、工作流、测试和发布方式继续以该仓库自己的 `README.md`、`AGENTS.md` 或
`CLAUDE.md` 为准。

职责与物理位置互相独立：仓库落在 `C:\workspace` 还是 WSL 的 `~/workspace` 由
`tier` 决定（见 [README.md](README.md)），而本文的路由规则只依据内容本身，
不因仓库换到哪个文件系统而改变。

## 基本原则

1. 每项事实正文只在一个权威仓库维护；其他仓库只保存完成本地任务所必需的简短
   结论和事实源指针。
2. 跨仓库引用统一使用 `repository:repo-relative-path#heading`，不写死
   `C:\workspace` 等机器路径。
3. “派生结论”必须是面向目标仓库职责重新表达的非敏感结论，不是复制来源正文、
   代码、数据或日志。
4. 进入目标仓库后，先读取并遵守其本地说明和工作树状态；中央规范不覆盖仓库自治
   规则。

## 内容路由

| 新内容 | 权威去处 | 来源仓库保留什么 |
| --- | --- | --- |
| 身份、任职、联系人、一对一聊天原文和沟通偏好 | `heliangos` | 不建立副本 |
| 项目群聊原文（以群为单位，与某条项目线直接相关） | 该项目线所属仓库；研究院项目为 `dut-institute-work:chats/` | 不建立副本；`heliangos` 只在联系人档案保留指针 |
| 沟通确认的研究院任务、分工、进度或会议结论 | `dut-institute-work` | `heliangos` 保留聊天证据、派生更新和事实源指针 |
| 博士学位论文原始正文、公式、图件、LaTeX 源码和最终定稿 | `xtu-phd-thesis` | `dut-postdoc` 只保留重新组织的可复用理论、派生结论和 `xtu-phd-thesis:repo-relative-path#heading` 指针，不整章复制论文正文 |
| 文献认识、科研路线、可复用方法和非敏感技术结论 | `dut-postdoc` | 项目或沟通仓库保留本地结论和事实源指针 |
| 个人拓扑优化软件的功能、缺陷、实现和验证结果 | `soptx` | 研究或项目仓库保留需求背景、研究结论和实现指针 |
| 工具、环境、配置、安装和跨设备迁移 | `workstation` | 业务仓库只保存确有必要的使用入口 |
| 算海仓库产生的可公开、可复用高层结论 | 与内容职责匹配的个人仓库 | 只保留非敏感派生结论和算海仓库指针 |

一条来源可以派生到多个仓库，但每个派生事实仍必须只有一个权威正文。例如，一对一
聊天原文留在 `heliangos`，项目群聊原文留在对应项目仓库的 `chats/`，其中确认的
项目进度进入 `dut-institute-work` 的项目文件，其中形成的通用技术认识进入
`dut-postdoc`；实现和验证代码只进入 `soptx` 或相应算海仓库。

原文归档与事实源是两回事：`chats/` 只承担「当时说了什么」的留证，不充当任务、
进度或结论的事实源；引用时仍指向项目文件，不指向聊天原文。

## 算海边界

- `soptx` 可以依赖 FEALPy 的公开接口，但不得复制、vendor 或重新托管
  `suanhaitech` 仓库中的算海代码。
- 算海代码、数据、运行日志、客户算例、凭据、内部路径和内部文档不得进入
  `brighthe` 个人仓库。
- 例外（2026-07-28 决定）：项目群聊原文按上表归档到项目仓库的 `chats/`，即使其中
  包含内部仓库名、构建配置或内部机器配置的表述。**凭据不在例外范围内**——账号、
  密码、Token、VPN 预共享密钥、私钥一律不得写入任何个人仓库；聊天中出现的凭据
  文件只记文件名与大小，不打开、不摘录内容。
- 例外（2026-08-04 用户明确授权）：`dut-institute-work:hpc/artifacts.md` 可登记
  指定内部文档的受控链接及登记时间，即使该仓库为 Public。链接仅作来源定位，不得
  复制或转存原件、正文、附件、源码、运行数据或凭据，且不表示任何人已获访问或再分发权限。
- 个人仓库引用算海事实源时，只记录完成个人仓库职责所必需的非敏感结论和
  `repository:path#heading` 指针。
- 是否可以公开某项内容不明确时，默认不写入个人 Public 仓库，先请求确认。

## 路由决策流程

1. 根据内容本身判断其职责域，不根据当前打开的仓库就近保存。
2. 找到上表中的唯一权威去处；无法唯一判断时列出候选并请求确认。
3. 写入兄弟仓库前读取其本地指令、README 和 `git status`。
4. 目标仓库缺失、无法读取，或目标文件存在难以安全合并的未提交修改时，停止对应
   写入并报告。
5. 写入后在来源处保留必要的派生结论与指针；不建立中央待办副本，不自动 commit
   或 push。
